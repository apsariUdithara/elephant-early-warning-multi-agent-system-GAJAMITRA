# CI and release configuration

The commit, branch, PR and release conventions are in the root `CLAUDE.md` under "Git, pull requests and releases". These rules cover the files that enforce them.

| File | Purpose |
|---|---|
| `.github/workflows/ci.yml` | Lint, test and build for `ai-service`, `backend`, `frontend` and the Claude Code guard hook |
| `.github/workflows/pr-checks.yml` | Commit messages (commitlint) and PR title format on every pull request |
| `.github/workflows/release.yml` | semantic-release on push to `main`, using the GitHub App token |
| `.releaserc.json` | Release rules: `feat` → minor; `fix`, `perf`, `revert` → patch; breaking → major; other types → no release |
| `commitlint.config.mjs` | The 11 approved types, no scopes |
| `package.json` / `package-lock.json` (root) | Pinned release and commitlint tooling only; not an application |
| `CHANGELOG.md` | **Generated by semantic-release. Never edit it by hand** |

- Changing any of these files changes how every future change is checked or released. Treat it as a security-sensitive change: explain it and get the user's approval first.
- Give every workflow an explicit `permissions:` block with the least access it needs. Only `release.yml` may write contents.
- Never add a second release process, create tags, bump versions or edit `CHANGELOG.md` manually.
- Never weaken a check (skip it, add `continue-on-error`, loosen a regex) to make a PR pass.
- Keep the type list identical in `CLAUDE.md`, `commitlint.config.mjs`, `.releaserc.json`, the PR-title regex in `pr-checks.yml` and `.claude/hooks/guard.py`. Change them together.
